# Ideas

The Lab's Proposer reads this file. Move an idea to `lab-notebook.md` once tried,
whether it worked or not.

## Ternary variants (Phase 1 / early Lab)

- **Per-dimension thresholds** instead of one threshold per vector — some dimensions
  are always small; a global per-dimension cut may keep more signal.
- **Tune `alpha`** (zero fraction) — the sweet spot between "binary with noise" and
  "too many zeros" is unknown; sweep 0.3 → 1.2.
- **Random orthogonal rotation before ternarizing** — spreads information evenly
  across dimensions so a fixed threshold hurts less (the ITQ / RaBitQ idea).
- **Per-vector scale stored as float16** — halves the scale overhead; check it does
  not change recall.
- **Rerank top-100 with int8 or float32** — ternary for the fast first pass, precise
  numbers for the final order; common in production, cheap to test.
- **Two-stage residual ternary** — ternarize the vector, then ternarize the error;
  about 3.2 bits/dim, likely between ternary and int8.
- **Matryoshka truncation + ternary** — keep the first 256 dims of a Matryoshka model
  then ternarize; two compressions might stack.
- **Asymmetric fast path** — keep the query int8 and use lookup tables against the
  two bit-planes, to get asymmetric quality at near-popcount speed.

## Baseline fairness

- **Int8 with per-dimension scaling** (not just per-vector) — the standard way; make
  sure our int8 baseline is not a straw man.
- **PQ with several `m` values** — PQ's memory is a knob; compare at equal bytes.
- **Binary with learned threshold (median per dim)** — the strongest simple binary.

## Bench infrastructure

- **Batched QPS** as a secondary speed number next to single-query latency.
- **Memory measured, not computed** — `nbytes` of the actual stored arrays, compared
  to `bytes_per_vector()` in a test.
- **Second embedding model (bge-small)** — a result that holds on two models is more
  believable.
- **Held-out datasets** (FiQA, SCIDOCS) reserved for verification runs only.
